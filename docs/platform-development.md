# Platform development

## Web

Run `npm run dev` for local development. Service workers are deliberately disabled in development.

Run `npm run build` and `npm start` to serve the production frontend and local Express API on port 3000 (or `PORT`). The browser app is in `dist`; server code is in `dist-server`. Vercel uses `npm run build:web` and the existing serverless handlers.

Run `npm run build:web` followed by `npm run preview` to test the static/PWA frontend. Preview does not supply the AI API. Local character generation still works.

PWA assets include all generated frontend chunks, local fonts, icons and backgrounds. The worker never precaches server output, API responses, authentication data or remote portraits. New versions wait until all old app tabs/windows close. Save a character before closing to apply an update; partially spun characters are not yet persisted.

## Native foundation

The Tauri scaffold bundles `dist-native`, generated by `npm run build:native`. This build disables service-worker registration. It uses the same React interface and rules as web. The current application identifier is a development placeholder, `local.summon.characterbuilder`; choose the permanent identifier before public distribution.

Commands:

| Command | Purpose |
|---|---|
| `npm run native:doctor` | Report Rust, C++ and Android tool availability |
| `npm run desktop:dev` | Run the desktop development shell |
| `npm run desktop:build -- --bundles nsis` | Build a Windows installer |
| `npm run android:init -- --ci` | Generate the Android project and Rust targets |
| `npm run android:dev` | Run on an attached Android device/emulator |
| `npm run android:build -- --debug --target aarch64` | Produce an ARM64 testing build |

Restart your terminal after toolchain installation so the new Cargo PATH and user-level `JAVA_HOME`, `ANDROID_HOME` and `NDK_HOME` variables are loaded. This setup uses Microsoft OpenJDK 21, the Android command-line SDK and stable NDK r29; Android Studio is optional for this command-line workflow.

The installed app requires a deployed HTTPS `VITE_API_BASE_URL` for online AI requests. A blank base URL is appropriate for same-origin web deployment, not native AI generation. Public Supabase settings can be shared; provider secrets must remain on the server. See `.env.example`.

Native shell compilation does not establish readiness for public distribution. Native file/share adapters, authentication return paths, lifecycle persistence, signing and real-device checks remain release gates. The CSP allows HTTPS API and portrait connections for this development shell; narrow these to actual deployed domains before release. Remote pages receive no native capability grants.

## Current validation

The Windows NSIS installer has been built. The compiled Windows application was tested through its real WebView2 runtime using an isolated profile: offline reload, automatic wheel completion, local template generation, saving and reopening the saved character all passed. The installer is an unsigned development preview, not a public release.

Android SDK 36, build tools 36.0.0, NDK 29.0.14206865, Microsoft OpenJDK 21, Rust and Visual Studio C++ tools are installed on this workstation. The ARM64 debug build now produces both packages:

- APK: `src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk`
- AAB: `src-tauri/gen/android/app/build/outputs/bundle/universalDebug/app-universal-debug.aab`

Despite the generated `universal` filename, this build contains only `arm64-v8a`. It requires Android API 24 or newer, targets API 36, and uses the development application ID `local.summon.characterbuilder.debug`. APK signature verification and 16 KB ZIP alignment checks passed. These are debug packages, not Google Play release artifacts.

Developer Mode is enabled on this workstation, but ordinary processes still received a symbolic-link permission error. Building in an administrator PowerShell succeeded. From that shell, explicitly change to the project directory, then run `npm run android:build -- --debug --target aarch64`. The scripts do not elevate themselves or change Windows settings.

The generated Gradle task invokes `npm run tauri`, so keep that package script alongside the desktop and Android convenience commands. Kotlin incremental compilation is disabled because Cargo sources on C: and this project on J: caused cross-drive cache failures. See [Kotlin's compilation documentation](https://kotlinlang.org/docs/gradle-compilation-and-caches.html).

The ARM64 APK passed a smoke test in LDPlayer 9.2.6.1 using its ARM translation: wheel completion, local generation with WebView networking disabled, local saving, and reopening the saved character after force-stopping and restarting the Android process. No JavaScript exceptions were recorded during these checks. Network emulation was restored afterward. The screenshot is `test-results/android-offline-character.png`.

For repeat testing, enable LDPlayer's local ADB connection, forward port 9224 to this app's `webview_devtools_remote_<pid>` socket, and run `node scripts/test-android-webview.mjs`. After restarting the app, update the forward to its new PID and run the script with `--reopen`. This test adds a local character and preserves existing saves. The direct CDP harness supports LDPlayer's older WebView, which rejects Playwright's browser-context setup.

A physical ARM64 phone check remains pending. Also check system Back, keyboard, screen insets, background/resume, and export/import behavior before release. Online AI is not validated by this smoke test; the current native build has no deployed API base URL and uses the local fallback when an AI request fails.

The npm native commands use a shared environment resolver so this installation's Java, SDK, NDK and Cargo tools can be located even before a terminal restart. Other machines can provide their own environment variables normally.

## Verification

`npm test` runs domain, API fallback, backup and worker-policy regression tests. `npm run build:web && npm run test:browser` runs real-browser offline checks. Windows tests use installed Edge; other hosts need a Playwright Chromium installation. `npm run lint` reports the repository's existing warnings.

The screenshot from the offline browser flow is written to `test-results/offline-character-mobile.png`. Test reports and generated build directories are ignored by Git.
